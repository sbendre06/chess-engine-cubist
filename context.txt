
I. The Ablation Design: "Peeling the Onion"
Instead of building four different engines, you start with one "Master Prompt" (the most detailed, high-context version) and systematically strip away layers to see where the logic breaks.
The Components of your Master Prompt:
Antichess Formal Rules (C): MUST HAVE - forced moves, win conditions
Foundation Model (FM): MUST HAV
Strategy (S): Single Strategy (0/1)  (x2)
Just summarize the deep research -> S - A pairs
Watkins paper
Architecture (A): Technical constraints based on Fairy Stockfish (Alpha-Beta pruning, UCI protocol, Move Ordering).
Persona (P): Role-playing (e.g., “world class software engineer at google”, “grandmaster chess player” Addition on top of everything


Plan Mode (one-shot, plan, plan-generated by better AI)
Total: 10 tests


The Ablation Branches:
Engine 1 (The Kitchen Sink): Contains C + S + A + P.
Engine 2 (No Persona): Contains C + S + A. (Tests if "Roleplay" actually adds value or just fluff).
Engine 3 (No Strategy): Contains C + A. (Tests if Claude can derive Antichess strategy just from the rules).
Engine 4 (No Architecture): Contains C + S. (Tests if Claude defaults to efficient code or if you must tell it how to prune).
Engine 5 (The Control): Just C. (The bare minimum).

II. The Execution Workflow
Friday Night: The "Parallel Burn"
Since you have 4–5 members, each person owns one ablation branch.
Task: Use your Claude Pro seat to generate the engine based on your specific branch.
Constraint: You are NOT allowed to help the AI. If it writes a bug, you can only say "Fix the bug," you cannot give it the answer. This preserves the integrity of the "Ablation Test."
Saturday Morning: The "Stress Test"
Run each engine through a "Correctness Suite."
Does it know it must capture?
Does it realize it won when its pieces were gone?
The Metric: "Mean Time to Illegal Move." (How many moves can it play against itself before it violates an Antichess rule?)

The Insight: If "No Persona" performs almost as well as "Full" but uses 20% fewer tokens, your conclusion is: "Persona-based prompting in complex logic tasks is a high-cost, low-yield heuristic." That is exactly the kind of insight a quant firm craves.

IV. Technical Implementation: The "Tournament"
To keep things fair, use a Single-Blind Test.
One person (The Librarian) collects all 5 Python files and renames them engine_1.py, engine_2.py, etc.
The rest of the team runs the tournament without knowing which prompt created which engine.
You guess which is which based on their playing style (e.g., "Engine 3 is playing like a standard chess bot—it's definitely the 'No Strategy' branch").

V. Final Pitch: "The Minimalist Engine"
Your presentation should focus on the "Sparsity of Logic." The Hook: "We didn't try to build the best engine. We tried to find the Information Threshold—the exact point where an LLM stops being a 'coder' and starts being a 'strategist.' Our ablation study proves that providing 'Architecture' instructions (Alpha-Beta) is 3x more valuable for win-rates than providing 'Strategy' instructions (Antichess heuristics)."
Why this is better:
It handles the "Cost" requirement: You are literally measuring the cost of each word in your prompt.
It’s a true experiment: Most teams will just keep adding to their prompt. You are the only ones systematically removing things.
It scales: This methodology can be applied to any task the hedge fund does (trading signals, risk parity, etc.).
How do you want to divide the branches? Should we assign the "Kitchen Sink" (most complex) to your strongest coder to ensure at least one version is highly functional?
